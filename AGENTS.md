# Training Planner project rules

## Releases

The user’s standing instruction is to finish, verify, commit, tag, push, and deploy each application update live. Deployment does not require another confirmation. Follow any later explicit instruction to hold or limit a release.

Use the requested version and preserve existing tags; never force-push or replace a release tag. Use the existing Hostinger deployment procedure, take private backups, verify live behavior and original-data integrity, remove disposable QA data and temporary deployment files, and update the release report with the result. Never commit credentials.

## Existing application

Extend the current Laravel, Inertia, and React application. Preserve working modules, authentication, ownership rules, history, and existing user data. Keep trainee self-promotion to Coach Workspace disabled.
