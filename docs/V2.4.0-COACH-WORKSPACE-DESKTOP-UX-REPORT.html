01

v2.3.9 baseline

Application baseline: v2.3.9, commit 70aae87c520ebb2bcb0af16e3245358d2b34b831. Work began from clean main at 5b8c017; later baseline commits contained deployment documentation. Existing auth, ownership, workout, history, progress, program lifecycle, scheduling and PWA engines were retained.

02

UX problems observed

The workspace gave several programs equal visual weight, repeated upcoming sessions for the same trainee, exposed scheduling internals too early, and constrained desktop content. The audit also found local dates serialized as UTC, current-program selection favoring a future run, and ambiguous block-specific workout choices.

03

Design principles

Current training first. Show the trainee, the next useful action, and the real schedule. Use existing white panels, navy text, blue actions, Lucide icons and typography. Detailed history and technical schedule differences remain available behind deliberate controls.

04

Desktop layout strategy

Coach-only layout rules use a wide content area with responsive gutters and a 2200px cap. Overview uses two columns; trainee Overview gives Current Training more room than This Week. Personal Workspace retains its existing layout.

05

Sidebar

Coach Overview, Trainees, Programs, Notifications, and Profile & Settings remain the primary destinations. Settings points to the Coach route and is tested to keep Coach context.

06

Coach Overview

Four compact metrics lead into Needs Attention and Today, followed by Upcoming and recent activity. No fixed-height internal session feeds. All data is authorized and computed by the existing Coach summary and session queries.

07

Needs Attention

Existing missed-workout, setup and coverage reasons drive named trainee rows with direct actions. Empty and pending-request states remain useful. An untimed workout today does not become missed before local midnight.

08

Today

Sessions are grouped by trainee with a compact identity header, workout thumbnails, time or Anytime, and state. Completed and skipped sessions remain distinguishable. Dates use explicit application-local YYYY-MM-DD serialization.

09

Upcoming grouping

One row per trainee includes the next eligible workout and the full next-seven-day session count. A window query selects the next occurrence; aggregation counts the entire eligible window rather than the former 12-row display sample.

10

Trainees

The existing live search and filters remain. Desktop uses operational columns for trainee, coaching, current training, this week, next workout and action. Mobile cards and contextual navigation remain intact.

11

Trainee workspace header

Identity and Training Planner ID stay visible. The header coaching badge reflects the subscription’s effective state, not a paused program or an attention flag. Training is the user-facing tab label.

12

Trainee Overview

Current Training and This Week appear together. Attention and up to five recent activities follow. Training goals remain available in secondary details; redundant overview statistics were removed from this screen.

13

Current Training

A shared card provides the authorized thumbnail, name, program position, start, progress, next workout where supplied, and View Training / Edit Schedule. No-training state offers assignment. Image preview remains separate from navigation.

14

This Week

Shows actual sessions with date, time and status. At most seven rows are shown with an explicit link to all workouts for the week. The completion total covers the full training set, not just the visible rows.

15

Attention

Existing domain reasons remain authoritative. Actions lead to the relevant trainee workflow; program controls and coaching subscription controls remain distinct.

16

Recent Activity

Compact completed/skipped workout rows with thumbnails and dates; up to five items, followed by History navigation. No fabricated performance is displayed for skipped sessions.

17

Training tab

Current Training is dominant. Additional assigned training is presented as compact rows, with historical material separated. The same server-selected current plan is used by Overview and Progress.

18

Current vs Other vs Past Training

No training, assignment, session, or program run is deleted or deduplicated by title. Different copies and historical runs remain inspectable; the display hierarchy does not rewrite ownership or history.

19

Programs page

Reusable templates use compact image rows with duration and weekly frequency. Assign is primary, View secondary; Edit, Duplicate and Delete are in the overflow. Distinct active assigned-trainee counts are shown. Search and type filtering are retained.

20

Program detail

Existing detail rendering is reused with thumbnails on block training-day summaries. Coach template detail leads to Assign and Edit Program; library overflow retains duplicate/delete actions.

21

Program Builder

The existing v2.3.9 builder, metadata, training-day editor, exercise library and Save & Assign behavior remain. Desktop space is expanded through scoped layout rules; no second builder was introduced.

22

Assignment flow regression

Training → Schedule → Review → Assign & Schedule still uses the existing draft, signed preview and atomic activation coordinator. Existing coverage, explicit extension, reuse, resume, renewal and protected existing-run behavior pass browser and backend regressions.

23

Schedule visual refresh

The main schedule and coaching coverage use the existing two-column layout. Multi-block weekly previews now identify the block and show one block at a time, preserving every authored prescription. Metadata shows days/week rather than counting repeated block definitions as weekly training days.

24

Edit Schedule

Weekly workout definitions appear first. A shared editor updates weekday/time choices through the existing training-day endpoint using an explicit schedule-only request. Current/completed program blocks remain protected; eligible future blocks can be edited. Calendar occurrences do not change until signed preview and confirmation.

25

Human schedule summary

Simple plans show unchanged workouts, revised dates, old dates to review and protected sessions. Program previews show actual old/new dates and times where available. Moving existing simple-plan occurrences requires explicit removal of obsolete eligible occurrences; this consent is not inferred.

26

Advanced schedule details

ADD / KEEP / REMOVE / PROTECTED remains the domain contract and is available in collapsed advanced details. Program progress and all scheduled weeks are also collapsed beneath the main editor and separate lifecycle controls.

27

Calendar

Existing month/week/list views, date dialogs, manual exceptions, drag/drop rules and permissions remain. The Coach CTA is Add Workout. Normal recurring setup stays in assignment and Edit Schedule.

28

Add Workout

Single-plan context preselects that plan. Multiple plans require a deliberate choice. Workout time remains optional. Recorded/program occurrences retain their existing edit restrictions; one-off additions use the original endpoint.

29

Unique Training Day selector

The server supplies authored training definitions, not generated occurrences. A multi-block program offers a block selector and its authored workouts: the QA program has 60 scheduled workouts, 15 definitions across three blocks, and five choices per block. Same-name definitions in different blocks are preserved.

30

Calendar details

Existing detail, image, status, one-off editing and workout-owner actions remain. Coach performance writes remain forbidden; the trainee records their own workout.

31

History

Existing search, period, type, status, pagination and ownership filtering remain. Duration, calories and recorded-weight summary use a dash for planned/skipped sessions rather than implying actual performance.

32

Progress

Coach metrics begin with completion rate, workouts/week, streak and recent PRs. One full-width Current Training card follows, with a separate program-history link. Existing weight trends, eligible structured sets and personal records remain authoritative.

33

Current Program logic

Server ordering prefers started active/paused runs, then future active/paused runs, then historical runs. The relationship query follows the same priority. ProgramRun currentFirst explicitly clears the relation’s previous ordering; all three trainee screens use TrainingContext.currentTraining.

34

Historical Program Runs

Independent same-name copies, earlier runs and personal runs remain. Coach queries only expose eligible assigned training. Browser regression verifies one current Coach card while both assigned runs remain in history and personal training stays private.

35

Consistency/adherence

Workouts/week divides completed training sessions by the selected period in weeks, with a minimum one-week denominator. Existing due/completed and consecutive-workout streak semantics remain. Zero/null actual weight never becomes a weighted PR or volume metric.

36

Status system

Blue identifies planned/current navigation; green identifies successful/completed states; warning/red states remain explicit. Coaching subscription state, program lifecycle and workout state are not conflated.

37

Typography/hierarchy

Existing font family and tokens are retained. Page titles, panel headings, program identities and secondary metadata have distinct sizes. Actions are grouped and secondary information does not compete with the main task.

38

Content-width improvements

Coach main content expands with the viewport instead of stopping at a narrow form width. Headers and card groups share the same container. Automated checks require useful desktop width and no page-level horizontal overflow.

39

Progressive disclosure

Template overflow, additional/past training, advanced schedule differences, program weeks and secondary trainee information are collapsed where appropriate. Nothing is removed from the data model.

40

Thumbnails

Shared TrainingThumbnail is reused for templates, assigned training, overview sessions, current training, block workouts and scheduling choices. Existing image fallback, preserved workout media and catalog media paths are retained.

41

Image preview

Full-image modal, original-image link, Escape/backdrop closing, focus return, nesting with other dialogs and keyboard use pass existing preview suites. Preview does not accidentally select a different training option.

42

Accessibility

Native buttons, links, labels, selects and details are used. Selects have explicit accessible labels; preview focus returns to its trigger. Responsive controls preserve existing mobile sizing. Automated nesting/overflow checks supplement visual inspection, not a formal accessibility certification.

43

Coach privacy

Existing CoachAccess, TrainingContext and ownership policies authorize reads and writes. New schedule-only writes revalidate under existing locks and forbid exercise/title/block payloads. Tests cover forged Coach/trainee context and preservation of exercises, media and Calendar entries before confirmation.

Architecture

Added focused Coach presentation components and a reusable weekly editor, plus one scoped stylesheet. Extended existing controllers/services/models. No alternate Calendar, history, progress, assignment, auth, or lifecycle engine.

46

Migrations/dependencies

No migrations and no dependency changes. React 19, Inertia 2, Laravel 12, existing Lucide and CSS continue. No schema, state-management or design-system replacement.

47

Bugs discovered

Future programs could outrank the current run; overview date JSON could display the preceding date; all block workouts looked like duplicate one-off choices; WebKit could receive overlapping refreshes after schedule save; the Progress current card inherited a half-width layout. Existing race receipt assertions also incorrectly depended on MySQL JSON object key order.

48

Bugs fixed

Centralized current ordering, explicit local-date strings, block-aware authored choices, refresh-complete saving states, full-width Progress card, bounded weekly display and clearer block previews. The concurrency harness now normalizes object key order while preserving strict value/type comparisons. No production data repair was needed.

49

SQLite

Complete suite: 632 tests, 12,466 assertions passed. Baseline was 624 tests. The eight added tests exercise grouped counts, local dates, current-program consistency, authored choices, stale schedule edits, protected blocks and authorization.

50

MySQL

The same complete 632-test suite passes against isolated training_planner_test. Normal application data is not used for database test resets.

51

Concurrency

All seven suites pass: Coaching 17, RecurringSchedule 4, Program 10, ProgramControl 15, Notification 10, CoachSetup 39, WeeklySchedule 5 — 100 checks. Independent PHP processes prove concurrent weekly edits accept one complete choice, reject the stale choice and leave exercise/occurrence data untouched before review.

52

JavaScript

All 38 existing JavaScript tests pass. Integrated client behavior is covered by real browser journeys rather than tests duplicating JSX implementation.

53

Desktop viewport testing

Mobile regression testing

320×480, 360×800, 375×812, 390×844, 430×900 and 768×1024 were exercised in both engines. Mobile uses the existing trainee context selector and stacked cards. These are browser viewport tests; no physical-device claim is made.
