1. What changed

Trainee accounts can no longer turn on Coach Workspace. The upgrade actions are removed from Profile and My Coaching, and the backend rejects attempts to use the old upgrade endpoint. An old browser tab or manually constructed request cannot bypass the restriction.

This is a focused patch on v1.7.0. Existing active coaches keep their coaching tools and editable coach profile. Trainees keep Personal Workspace and My Coaching for connecting with a coach.

Coach registration remains available when creating a new account. This patch prevents an existing trainee account from upgrading itself; it does not introduce an approval system for new coach registrations.

Existing coach accounts are not demoted. Inactive coach profiles and inconsistent role/profile combinations cannot use this endpoint to activate themselves.

3. Server enforcement

  • GET /profile/coach checks the existing User::isCoach() rule before rendering: the account must have the coach role and an active coach profile.
  • POST /profile/coach applies the same check before validation, then rechecks the loaded account inside the existing transaction after acquiring its user-row lock.
  • The handler is now updateProfile. It updates display name, specialization and bio on the existing profile. The old profile creation, role promotion and forced activation code is removed.
  • Submitted account_type, is_coach and active fields cannot grant access. Guests continue to be redirected to login.
  • Existing workspace-switch and coach-route authorization remains in place. The denial message now says the page is available to active coach accounts only.

4. Interface changes

Profile and My Coaching render the Coach profile link only when the authenticated account is an active coach. The account menu was already gated correctly and needed no change.

The coach profile form is now explicitly an editing screen: “Coach profile”, “Manage your coaching name and information”, and “Save coach profile”. The upgrade callout and conditional enable-button copy are removed. Saving still redirects an existing coach to Coach Overview with “Coach profile updated.”

Existing layouts, navigation structure, styling and authentication were reused. My Coaching, Training Planner ID and QR connection controls remain available to trainees.

  • No measured horizontal page overflow at those widths.
  • Trainee pages contain no coach-profile link or Enable Coach Workspace action. The trainee account menu contains Profile and Log out, without coach tools.

  • The mobile coach profile was visually inspected. No browser console warnings or errors were observed in the QA tab.

Checks used two disposable local accounts in an isolated localhost browser tab. The accounts were deleted, the tab closed and the viewport override reset.

8. Data and architecture preservation

All 17 application-data table hashes and all 44 media-file hashes match the fresh pre-QA snapshot after cleanup. Only the disposable QA accounts were created and removed. Existing plans, sessions, history, actual results, coaching relationships and profiles were not changed.

This patch adds no migration, table, column, index, dependency, queue, worker or new role system. The existing Laravel/Inertia/React architecture and account model are retained.

No production account, file, database or deployment setting was changed during this source release.

9. Release and delivery

Version: v1.7.1. Baseline: 941bb0e / v1.7.0. Delivery is the main branch and a separate annotated v1.7.1 tag in AhmadDalao/traningApp. Existing release tags are preserved.

Hostinger is unchanged. This report describes a GitHub source release, not a live deployment. Production remains on the previously deployed v1.6 stabilization code; the restriction takes effect there only when the updated code is deployed.

The patch itself requires no database migration. Deploying the complete v1.7.1 tree over production’s v1.6 baseline also includes v1.7.0 and therefore requires that version’s existing additive migration, rebuilt frontend assets, and normal release verification. Preserve production environment settings and uploads.

10. Future maintenance and rollback

No admin promotion screen or coach-approval workflow was added. If selected trainees should become coaches later, that should be an explicitly authorized account-management feature; the profile editor is no longer a promotion mechanism.

Previously upgraded coaches remain coaches. Retroactively changing those accounts would be a separate policy and data task.

A code revert can restore the previous implementation without a patch-specific schema rollback, but it would also restore trainee self-upgrade. Keep that consequence explicit when planning a rollback.

No unresolved defect was reproduced in the completed patch checks. Production smoke tests were not run because this patch was not deployed live.
