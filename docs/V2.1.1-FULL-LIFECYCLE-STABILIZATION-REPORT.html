QA methodology

Capture original local row fingerprints and media hashes; use disposable, privately tracked accounts; run SQLite and isolated MySQL sequentially; exercise real UI workflows in Chromium and WebKit; reproduce failures, add regressions, make narrow fixes and rerun the whole suite. Browser tests run sequentially when sharing a trainee because the product permits one active workout per account.

Registration, onboarding, plan building, consent, assignments, workouts and controls in the new full lifecycle suite use real UI actions. Private fixtures supply past dates, long histories and concurrent run states. Automated assertions are supplemented by visual inspection of mobile run, paused, History and coach screenshots.

29 / 50

Technical debt

TECH-DEBT-01 · ExerciseEditor.jsx (590 lines)

Library choice, custom media and nested superset-partner editing share a sizable stateful feature.

Risk: Future editor changes could regress nested focus or draft preservation.

Why deferred: Current behavior and keyboard restoration pass; splitting state ownership now would add stabilization risk.

Next direction: When changing partner editing, extract that meaningful flow with existing behavior tests; avoid tiny markup-only components.

TECH-DEBT-02 · app.css (3,005 lines) plus feature/mobile styles

The original global stylesheet remains large and mobile rules override some base selectors.

Risk: Future broad selectors can unintentionally affect unrelated features.

Why deferred: No conflicting rule requiring a broad rewrite was reproduced; mobile regressions pass.

Next direction: Move cohesive feature rules only when touching that feature, keeping shared tokens and mobile precedence explicit.

TECH-DEBT-03 · ProgramLifecycle cards / paginated run history

Each displayed run is synchronized and its position read; work is bounded by six cards or twelve rows but repeats reads per run.

Risk: Larger accounts can make these pages slower; current measured timings remain acceptable.

Why deferred: Combining synchronization with list reads changes transaction/locking behavior. The per-workout query explosion was fixed separately.

Next direction: If measured latency grows, return a synchronized position once per run or batch the read side while preserving row-lock and reopening tests.

Bugs found

BUG-01 · History session actions Medium

Viewport: 320–1280 px; both engines

Reproduction: Open a retained past, unresolved workout from an ended program through Training History.

Expected: History and Calendar expose the same hold and omit forbidden workout/edit actions.

Actual: History omitted programHeld, so the shared page advertised actions rejected by the server.

Root cause: TrainingHistoryController did not pass the existing ProgramRun::holds result to the shared detail page.

BUG-02 · Progress training completion rate Medium

Viewport: All viewports

Reproduction: Pause a program from 5 November, advance to 20 November, leaving two earlier workouts unresolved.

Expected: Only the two uncovered workouts are due; held workouts do not penalize the rate.

Actual: Progress counted covered paused workouts, unlike the program and coach overview.

Root cause: ProgressController omitted the shared availableOnSchedule scope.

BUG-03 · Program Start feedback Medium

Viewport: 390 px; Chromium and WebKit

Reproduction: Open the same active run in two tabs. Pause it in one, then press Start workout in the stale tab.

Expected: An actionable server rejection appears.

Actual: Start silently refreshed state with no explanation.

Root cause: The run page POST had no onError handler.

BUG-04 · Early program History status correction Medium

Viewport: 390 px; both engines

Reproduction: Complete a future program session early; open its History detail and change it back to Planned or Skipped.

Expected: Land on a valid session detail after the status change.

Actual: The redirect returned to a History URL that no longer qualified, producing 404.

Root cause: The status endpoint always redirected back despite changing History eligibility.

Known limitations
