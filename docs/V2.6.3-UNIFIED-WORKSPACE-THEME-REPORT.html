Training Planner · Release v2.6.3 · 10 November 2026

One theme. Both workspaces.

The supplied visual style now applies across the application, with one shared Settings experience.

READY — DEPLOYED AND VERIFIED

1. Baseline and scope

Accepted production baseline: v2.6.2 (e7a3a986a511e4526f1121e3375ae7de91f2aa7e). Starting main commit: 9ceed7b1a8ec606b353a93803023b498cce0868f. Existing Laravel 12 / Inertia 2 / React 19 architecture retained. The previous theme applied only to Coach and the Personal Dashboard; other Personal pages and older Settings routes still used earlier layouts.

2. Shared application theme

All authenticated pages now use the same workspace shell, navy desktop navigation, purple desktop accents, pale background, white rounded panels, consistent fields, buttons and breadcrumbs. Mobile retains the supplied blue treatment and a five-destination bottom navigation. Plans, programs, calendars, workout logging, history, progress, coaching, subscriptions, setup, account pages, authentication and the offline fallback share the styling.

Personal navigation now correctly recognizes plan discovery, program runs, schedules and Settings aliases. Page headings wrap, forms use available width, short desktop navigation scrolls, plan-card actions align, and mobile controls retain 16px input text with space above the bottom navigation.

3. One Settings experience

Profile, Edit Profile, Training Preferences, Notifications and all Coach Settings aliases render the shared SettingsPage component. Both workspaces use the same desktop section rail and mobile directory/detail/back flow. Coach profile and account details remain distinct fields within that shared design. Personal profile, goals, body measurements, notifications, installation and device controls are preserved.

Save stays in the current section. Invalid fields open the relevant section. Saves are disabled offline. Mobile detail screens have a visible semantic heading. Device and push controls reuse the existing implementation without another standalone Settings layout.

4. Data handling and authorization

Existing profile normalization and body-weight recording were extracted into ProfileSettings and reused under the existing locked-user transaction. Combined profile/preferences/notification saves validate before writing. Repeated unchanged weight saves do not create another entry. Earlier weight history remains intact. SettingsPageData shares response data, device-cookie handling and private no-store headers.

Tests verify actor-only updates, rejected forged account metadata, invalid-input rollback, existing Coach restrictions and no trainee promotion. No subscription, assignment, workout, schedule, history or PR domain algorithms changed. No schema migration is needed.

5. Regression findings fixed

  • Theme scope restricted to Coach and one Personal page.
  • Different Profile, Notifications and Coach Settings layouts.
  • Missing Settings navigation state on preference and legacy routes.
  • Offline Settings save buttons remaining enabled.
  • Save leaving the selected section.
  • Mobile detail title lacking heading semantics.
  • Personal device section missing the shared layout class.
  • Inconsistent dialog, authentication and offline-screen styling.
  • Uneven plan-card action placement and mobile controls needing scroll clearance.
