Mobile-first method

Tested 320, 360, 375, 390 and 430px, then 768 and 1280px. The principal matrix covers 62 page/account states × 7 widths, with document scroll-width measurements, visible input/button sizing and console capture. Additional checks cover all six coach trainee sections × 7 widths, long-name day/workout screens, dialogs, and interactions. Browser regressions run against both Chromium and WebKit; the app’s native web preview independently confirmed the 44×44 close control, 16px input and restored focus.

Real browser interactions include typing, selecting, submitting, navigating, confirming/cancelling dialogs, dragging calendar events and recording workout sets. A 320×480 viewport exercises constrained-height forms and menus. Five disposable accounts (two trainees, three coaches), 54 extra stress sessions, long unbroken names, Unicode notes, custom exercises, repeated sessions and structured workout results exercise populated states.

Scope of evidence: these are automated desktop-browser viewport tests and native preview checks, not physical iPhone/Android hardware tests. A short viewport approximates the available space with a keyboard; it does not certify every mobile keyboard or browser-zoom behavior. Dense month cells remain naturally narrower than 44px at 320px; Month/Week/List and the explicit Change date flow provide usable alternatives to dragging.

Completed coaching lifecycle

Disconnect immediately denies coach access while the trainee keeps records.

Confirmed defects and fixes

One High and seven Medium defects were reproduced, fixed and retested. No known Blocker or High defect remains in the audited scope.

M01 · MediumFIXED & RETESTED

Auth and shared forms · 320–430

Reproduce
Open registration or a plan form on a phone-width viewport.
Expected
Inputs should remain readable without focus zoom.
Before
Auth inputs rendered at 12px.
Root cause
Small component font rules overrode inherited form sizing.
Fix
Shared mobile input/select/textarea rules enforce 16px and a 44px control height.
Regression / retest
Measured fonts in page matrix; Chromium and WebKit login regression.
M02 · MediumFIXED & RETESTED

Shared controls · 320–430

Reproduce
Open a modal, calendar, plan list or workout builder.
Expected
Primary and icon controls should be comfortable to tap.
Before
Menu and modal close targets measured 31×32px; compact actions were 32–41px tall.
Root cause
Desktop compact sizing was reused on phones.
Fix
44px mobile button/icon/summary targets; wrapping action rows and weekday labels.
Regression / retest
No undersized visible buttons in the 320px matrix; close target verified 44×44 in both browser engines and native preview.
M03 · MediumFIXED & RETESTED

Dialogs and copy/superset flows · 320/390

Reproduce
Open Create training plan, press Escape; repeat through copy and nested superset dialogs.
Expected
Keyboard focus should return to the visible opener.
Before
Focus fell to BODY; nested replacement and hidden copy-menu buttons lost the useful return target.
Root cause
Dialog unmount discarded native focus restoration; Safari does not focus clicked buttons.
Fix
Remember/restore the opener, focus shared clicked buttons, retain the original exercise opener, and return copy dialogs to the visible summary.
Regression / retest
Three dedicated regression cases pass in Chromium and WebKit; native preview returns focus to Create training plan.
M04 · MediumFIXED & RETESTED

Planned session actions · 768

Reproduce
Open a planned session containing Start, status, Change date and Edit actions.
Expected
Actions should wrap within the viewport.
Before
Document/action row extended to 905px in a 768px viewport.
Root cause
A tablet rule removed the action-row width cap.
Fix
Cap header actions at 100% and wrap; allow title containers to shrink.
Regression / retest
Session page and seven-width matrix pass; desktop 1280 rechecked.
M05 · MediumFIXED & RETESTED

Training History · 768

Reproduce
Open populated personal and coach History at tablet width.
Expected
Readable history with scrolling contained inside its panel.
Before
896px document extent; long table cells became narrow vertical text columns.
Root cause
Card breakpoint stopped at 760px; positioned table content lacked a containing block.
Fix
Use existing History cards through 1100px; position table scroll containers locally.
Regression / retest
Personal and coach History pass at all seven widths; Today/custom/type and 10/25/50/100/All controls exercised.
M06 · MediumFIXED & RETESTED

Long-name day detail and breadcrumbs · 320–1280

Reproduce
Save a valid long unbroken plan/day name and open its detail page.
Expected
Names should wrap without horizontal page scrolling.
Before
Document extended to 797px at a 320px viewport.
Root cause
Breadcrumb and metadata flex children retained intrinsic text width.
Fix
Constrain/shrink those children and allow long-token wrapping.
Regression / retest
Long-name day and Active Workout pass at all seven widths; before/after evidence below.
M07 · HighFIXED & RETESTED

Personal/Coach navigation · 320×480

Reproduce
Open mobile navigation on a short screen and try to open the account menu.
Expected
Profile, workspace switch and logout must remain reachable.
Before
Account button ended at y=677 and sidebar content at y=733; neither could be scrolled into view.
Root cause
Fixed sidebar allowed visible overflow instead of becoming a scroll container.
Fix
Scrollable sidebar with contained overscroll and nonshrinking navigation/account sections.
Regression / retest
Profile and four workspace-switch selections pass at 320×480 in both engines.
M08 · MediumFIXED & RETESTED

Workspace/account menu · 320×480

Reproduce
Choose the already active workspace, then try another destination.
Expected
Every menu selection should close navigation consistently.
Before
Same-workspace navigation kept the menu open; the next toggle hid the account controls unexpectedly.
Root cause
Closing depended only on the URL changing.
Fix
Close both menu states when a user-menu link or button is activated.
Regression / retest
Personal→Personal→Coach→Coach regression passes in Chromium and WebKit.

Security and data preservation

All 17 original table fingerprints and 44 original media hashes match the pre-QA snapshot. Cleanup removed 5 disposable accounts and 130 QA media files. The cleanup checks every remaining media reference before deleting an extra file, and verifies the full original snapshot afterwards.

Backend and authorization code is unchanged. Trainees still cannot enable Coach Workspace or forge a workspace switch. Coaches cannot write trainee actual workout results. Existing tests verify cross-user/cross-coach substitution, paused/ended/expired services, disconnect, protected active/completed sessions, expired and consumed QR tokens, stale schedule/progression tokens and concurrency. Current completed status remains the source for Progress; null/zero weight is not fabricated into weighted metrics.
