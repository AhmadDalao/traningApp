What was added

  • Optional three-step onboarding: About you, Your goals, Your training. Registration retains its existing four fields and immediate login. Skipping is remembered; setup remains available from Profile. Completing onboarding does not add a plan.
  • Profile: available from the existing sidebar avatar/user menu and desktop topbar avatar. Personal information, training preferences, and body-weight goals are editable.
  • Recommended plans: three suggestions selected from six small presets. Review the exercises, then choose Use this plan to copy it into normal editable Training plans. Dates and weekdays remain unset, so no Calendar sessions are silently created.
  • Progress: one new primary navigation item. Dated body-weight recording, editing/deletion, current and target weight, change, goal progress, a small SVG trend chart, recent-entry pagination, and monthly training statistics.
  • Weekly check-in: an optional Overview card when tracking weight and the latest measurement is at least seven days old, or no measurement exists. Not now dismisses it for seven days.
  • Completed sessions: optional actual duration and manually entered calories, added after the existing one-click completion action. Values appear in the existing Training History and session detail pages.
  • Clear terminology: exercise labels now say Planned Weight and Actual Weight Used; Profile and Progress use Current Body Weight and Target Body Weight. Existing target_weight storage is unchanged.

Recommendations

The six presets are Full Body, Upper / Lower, Push / Pull / Legs, Mixed Fitness, Cardio & Conditioning, and Mobility & Flexibility. Missing goal, experience, days, equipment or duration shows a Complete profile empty state.

  • Goal matches receive first priority. Beginner favors Full Body; four available days favor Upper / Lower; five or more favor Push / Pull / Legs for a muscle goal. Endurance and mobility goals prioritize their matching routines.
  • Upper / Lower and Push / Pull / Legs require intermediate/advanced experience, enough days, and a full gym or dumbbells. Other presets use up to the available day count.
  • Equipment changes actual exercise choices. Short sessions use fewer exercises and sets; experience adjusts sets; strength goals use a lower rep range. Cardio duration adapts to the selected session length. These are editable starting routines, not timed-session guarantees.
  • The top three suggestions include a reason and alternatives where appropriate. Body measurements and BMI are not used to infer the user's goal.
  • Use this plan validates the current preferences and copies exercises with independent media into an owned plan. Planned weights remain blank; the normal schedule preview is still required.

Body-weight history and progress

A changed profile weight appends a measurement dated today. Re-saving the same value does not duplicate it. Explicit Record weight always creates an entry. Leaving the profile weight blank preserves recorded history; editing or deleting measurements is done in Progress.

  • Current: latest recorded date, then newest ID for ties. Backdated records do not replace a newer measurement. Updating/deleting records recalculates the profile's current weight; deleting the last measurement clears it.
  • Starting: earliest recorded date and ID. Change: current − starting. Remaining: absolute difference between current and target.
  • Goal progress: (current − starting) / (target − starting) × 100, clamped to 0–100%. It appears only for a target that is below the starting value for Lose or above it for Gain. No valid denominator/direction means a dash.
  • Monthly training: counts training sessions due this calendar month, through the current date/time in the application timezone. Completion rate = completed / all due training sessions, including skipped and uncompleted planned sessions. Rest days and future sessions are excluded.
  • Weekly check-in: requires Maintain/Lose/Gain tracking and an old or missing measurement. Not now persists for seven days. Recording a recent measurement removes the prompt. No scheduler, notification or blocking dialog is used.

Duration, calories and historical compatibility

Mark completed still saves the status, completion timestamp and original snapshot immediately. The completed training session then offers optional Workout details: duration 1–1,440 whole minutes and calories 0–20,000 whole kcal, or blank. The server sets source to manual; the UI says Manual / wearable. There is no automatic calorie estimate or wearable integration.

These values belong to the session, not the exercises or user profile. The existing version-1 snapshot continues to hold exercise prescriptions and actual weights. Editing session details never changes that snapshot. Old records may have no duration/calories. Status reversal preserves details for later completion but hides them from incomplete/skipped history rows. Rest days do not accept these workout metrics.

Live release and remaining scope

Deployed and verified as v1.1.0 on 27 October 2026. The live site is training.ahmaddalao.com; source is tagged v1.1.0. The previous v1.0.0 tag is preserved.

For future deployments, follow the existing README Hostinger update process: back up production data/uploads, preserve .env and APP_KEY, upload changed application files and rebuilt assets, run the additive migration, clear/rebuild production caches, then verify authentication, old history, new Profile/Progress, and completed-session details. Do not run fresh migrations or seeders against production. The migration's down method removes the newly collected data, so do not use rollback as a routine code rollback after users start recording measurements.

php artisan migrate --force
php artisan optimize:clear
php artisan optimize

Automatic calorie estimation is deliberately left as the optional follow-up permitted by the brief. Any future estimate must be clearly labelled and use sufficient inputs. Wearable APIs, AI, nutrition, per-set logging and advanced analytics remain outside this update. No known blocking implementation issue remains after the listed checks.
