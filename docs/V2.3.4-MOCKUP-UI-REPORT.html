01

Baseline and version

The supplied brief targets v2.3.3, but that immutable release was already deployed before this task. This follow-up continues from v2.3.3 source 61a7286 and documentation HEAD 8cc6fcf. It is released as v2.3.4 so all earlier tags remain untouched. The prior v2.3.3 implementation and deployment report remains historical evidence.

02

Coach privacy architecture

The deployed server-side CoachAccess authorization remains the source of truth. The visual work does not broaden Coach access to a trainee’s personal training or another Coach’s assignments. Privacy tests were rerun on both databases and browser engines.

03

Assignment scoping

Existing assignment-based scopes remain shared across trainee routes and queries. Owning a plan as a trainee is still insufficient to expose it to a connected Coach.

04

Program privacy

The Program tab continues to show training assigned by the authenticated Coach. Current training appears once in the overview; other legitimate assignments remain available in the Program context.

05

Calendar privacy

Coach Calendar retains the existing assignment-scoped session queries. The lighter shell changes presentation only; unrelated workout names and prescriptions are not added.

06

History privacy

Coach History remains scoped to the authenticated Coach’s assignments. Completed and skipped records keep the accepted History visibility behavior, including untimed and early-completed records.

07

Progress privacy

Coach adherence, exercise highlights and records retain the assignment scope. Body-weight visibility remains governed by existing consent. Personal Progress continues to use the user’s own full history.

08

Direct-route protection

The full feature suites and privacy HTTP checks pass for unauthorized personal and other-Coach plan access, scheduling, history and progress. Frontend hiding is not used as authorization.

09

Assign to Trainee

The existing immediate trainee list and assignment states are retained. Initial avatars, tighter rows and consistent action spacing implement the mockup while mobile still uses cards.

10

Live trainee search

The shared existing React/Inertia filter behavior remains: debounced text, immediate discrete criteria, no Search button, bounded server-side results. Search and clear flows pass in Chromium and WebKit.

11

Duplicate assignments

Existing duplicate detection and explicit separate-copy actions remain unchanged. Atomic setup and assignment tests verify reuse and rejection of unintended duplicates; this update adds no copy path.

12

Plan Discovery

Search and filters stay above recommendations. Three concise recommendation cards lead into compact horizontal catalog rows on desktop and stacked cards on mobile.

13

Recommendations

Recommended labels and actual matching reasons remain visible. No invented match percentages or training results were added. Preview and use actions continue through existing routes.

14

Live filter architecture

No Livewire, dependency, second filter framework or new frontend architecture. The existing shared React/Inertia hook remains responsible for debounce, request handling and partial updates.

15

Filter URL state

Existing URL criteria and history replacement are preserved. Browser checks cover live search, discrete filters, focus and result restoration in the established workflows.

16

Unified Progress

The unified dashboard now has a tighter visual hierarchy and desktop grouping. Exercise highlights and body-weight content share the lower layout; phone widths stack naturally. Detailed drill-down routes remain available.

17

Personal Progress

Training summary, consistency, active programs, recent records, exercise highlights and body-weight information remain together. Empty states use real availability rather than fabricated charts.

18

Coach Progress

The same dashboard presentation remains read-only in Coach context. No weight entry, workout completion or performance-write controls are introduced for Coaches.

19

Program Progress

Run cards now include an icon, current week/block and a progress bar. The percentage is exposed from the existing ProgramLifecycle position calculation, with no new formula or query.

20

Exercise highlights

Existing structured workout results continue to drive compact highlights and exercise detail links. Zero and missing actual weights do not become weighted records.

21

Personal records

The current PR engine remains unchanged. Current completed status, positive-weight rules, repetitions and duration handling are preserved by the regression suites.

22

Body-weight section

Existing chart, entries and target information are retained in a compact section. No new Coach permission or write action was added.

23

Trainee Overview

The header now focuses on trainee identity and coaching state. Current training appears once beside service status, followed by three quick cards for next workout, this week and progress. Normal subscription and program actions remain distinct.

24

Schedule Workout

The existing assigned-plan and single-day preselection, optional time and Anytime interaction are preserved. Consistent full-width panels, spacing and shared icons make the form match the trainee context.

25

Schedule Manager

Add / Keep / Remove / Protected / Outside service date summaries remain actionable. Lists initially show eight rows with View all; every reviewed row remains available. Signature, selection and schedule mutation behavior is unchanged.

26

Coach Overview

Architecture

The application remains Laravel + Inertia + React. One scoped presentation stylesheet and one initials component were added. Only two additive read props changed in PHP: latest completed workout and existing program progress percentage. No migrations, dependency changes or competing domain services.
