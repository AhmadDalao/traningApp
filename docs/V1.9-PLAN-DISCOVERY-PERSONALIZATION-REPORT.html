1. Baseline and scope

Accepted production baseline: v1.8.0, tagged at 0f88fc3; starting main commit c828e99. The working tree was clean. Baseline verification passed 419 PHP tests / 5,386 assertions, 24 JavaScript tests and the production build.

v1.9.0 extends the existing Laravel + Inertia + React + Vite application. Authentication, layouts, navigation, MySQL ownership rules and prior modules remain in place. No framework, service, package or background worker was introduced.

2. Three ordered goals

Profile and onboarding accept zero, one, two or three optional goals. The chosen array order means Primary → Secondary → Supporting. Shared controls allow removal, clearing and moving a selected goal up or down. A fourth choice is explained without replacing a selection.

The shared Laravel request validates an ordered list of at most three distinct known goal keys. Duplicate, unknown, non-list and four-goal submissions are rejected before any profile or weight write.

3. Legacy-goal compatibility

The existing JSON training_goals field is reused. On save, training_goal stays synchronized to the first goal, or null when cleared. Older single-goal records retain the existing read fallback. Reading a profile does not backfill rows or reopen completed onboarding.

4. Returning-user preferences

The new authenticated GET /training-preferences opens the existing three-step form in editing mode. DOB, height, current weight, ordered goals, level, days, duration, equipment and body-weight goal are prefilled. PUT /training-preferences saves preferences and opens updated recommendations.

5. Reused onboarding and form components

Onboarding/Index and ProfileFields remain the shared implementation. Returning mode changes the title, save route and Cancel action. Initial onboarding retains Skip, Back, Next and completion behavior. Existing Profile/Edit also uses the same three-goal controls.

6. Cancellation, completion state and body weight

Cancel is read-only navigation to Profile. Returning saves do not update onboarding_completed_at or onboarding_skipped_at. An unchanged body weight does not create another history entry; a changed value uses the existing BodyWeightHistory service. Both previously completed and skipped onboarding states are tested.

7. Discovery entry points

  • Profile: Update preferences & find a plan plus Find a training plan.
  • Personal Training Plans: Find a training plan alongside the existing create action.
  • Browsing is available without completing or changing a profile. Coach template and assigned-plan management screens retain their existing controls.

8. Curated catalog: 19 plans

9. Beginner routines

Full Body 2 Days and 3 Days use dumbbells and floor space. Gym Foundations introduces gym machines and free weights. Bodyweight Foundations requires no gym equipment. Conditioning & Mobility pairs easy outdoor activity with dedicated mobility work.

10. Intermediate routines

Upper/Lower, PPL, PPL + Full Body, Body Recomposition, Strength, Hypertrophy, Bodyweight Strength and Cardio & Conditioning provide different splits, movement mixes and prescriptions. Resistance, duration and paired accessory work use the existing exercise model.

11. Advanced routines

Six-day PPL, Upper/Lower + Arms, Powerbuilding, Advanced Hypertrophy, Strength + Hypertrophy Hybrid and Advanced Bodyweight cover different frequency, strength and volume choices. Advanced Bodyweight uses floor space and explicitly describes its equipment limitations. Advanced labels are informational; no experience-based selection lock exists.

12. Recommendation ranking

The existing PlanRecommendations service ranks the code-based catalog deterministically. Primary, Secondary and Supporting goal matches contribute 140, 70 and 35 points. Matching the template’s main focus adds 50, 25 or 12 respectively. No goal-pair permutation table is used.

Matching experience adds 45; more advanced mismatches subtract 60 per level and easier mismatches subtract 20 per level. Exact days add 50; differences subtract 22 per day, with a further 15 penalty when more days are required. Equipment fit adds 65; unavailable equipment subtracts 130. Exact duration adds 15; other durations subtract the minute difference. Ties retain catalog order. Scores are internal, not percentages shown to users.

13. Matching explanations and fallback

Cards explain only actual goal, level, day, equipment and time matches. Bodyweight needs no gym equipment; home-gym users are invited to specify dumbbells when available. Missing preferences receive useful beginner/general-fitness options using simple fallback bonuses. BMI and body-weight goals do not choose training goals or alter ranking.

14. Recommended and All Plans sections

Three ranked recommendations appear above the complete 19-plan library. All levels remain browseable and selectable. Discovery payloads contain card metadata only; full exercise details load on the selected preview page. No catalog pagination or search service is needed for this dataset.

15. Search and filters

Search matches names, descriptions, goal labels, level/equipment labels and weekly split text. Level, goal, days and equipment combine using AND. A shared modal has Clear and Show plans controls, a result count and an empty state. Mobile avoids a crowded row of dropdowns; desktop uses the same compact control.

16. Full plan preview

A dedicated page shows level, supported goals, weekly commitment, estimated duration, equipment, a linked weekly split and each day’s actual exercise list. Images, sets, reps/duration, supersets and useful notes are visible. Native expandable day sections support keyboard interaction. Use this plan is available at the top and bottom.

17. Use This Plan behavior

Explicit selection validates an enabled catalog key and creates a normal personal plan, training days and exercises for the authenticated user. Dates and weekdays remain unset and scheduling remains disabled until the user reviews and applies a schedule. Target weights remain null.

18. Exercise identity and copy independence

Every prescription resolves an existing builtin: library key. Name, icon and image come from that identity; there is no name-based matching or filler exercise generation. Sets, reps, tracking mode, notes and superset groups are copied. Uploaded thumbnails receive independent paths. Selecting the same template twice creates separate editable plans; future catalog changes do not synchronize into either copy.

19. Data and transaction protection

No existing plan, active session, calendar record, workout snapshot or structured set is rewritten when preferences change or a plan is selected. Media-copy failures roll back the new plan and remove partial copied files. Tests verify independent copies, transaction failure cleanup, stable identity into structured logging, and zero-weight reps without fabricated weight PRs.

20. Coach Personal Workspace

Coaches use this discovery flow for their own personal plans. Actor and owner remain the signed-in coach. Coach templates, subscriptions, trainee assignments, shared scheduling and consent are not repurposed into a marketplace. Full personal lifecycles pass for both trainee and coach accounts; existing coaching regressions and concurrency checks pass.

21. Trainee account policy

Trainees still cannot enable or switch to Coach Workspace. Forged role fields in preference and copy requests do not change capabilities or ownership. Existing coach registration remains separate. Direct trainee upgrade attempts are rejected in automated and authenticated HTTP checks.

22. Mobile implementation

The new CSS starts with a 320px single column, then adds a second column at 760px and a third at 1200px. Long plan and exercise names wrap. Preview exercises use rows instead of a wide table. Mobile form inputs use 16px text. Primary controls and goal-order buttons are at least 44px high.

23. Required viewport verification

Twenty responsive checks cover Discovery, advanced Preview, returning About You and three-goal controls at 320, 360, 390, 430 and 1280px. No document-level horizontal overflow was observed. Card grids use one column on the tested mobile widths and three at 1280px.

24. Desktop verification

At 1280px, cards and metadata expand into columns within the original application layout. Shared controls, full previews, goal priorities and long names remain usable. The desktop work preserves the existing sidebar and Personal/Coach context.

25. Accessibility checks

Native labels, buttons, dialog, details, landmarks and live result/goal messages remain in use. Keyboard testing found and fixed focus loss after dismissing Filters. Focus now returns to the trigger; new controls show a visible 2px focus outline. Escape closes the dialog. Images are decorative beside exercise names.

26. Touch and short-viewport behavior

At 320 × 480px, the filter dialog scrolls and its action buttons remain reachable. Select controls retain 16px text and approximately 45px height; the close control is 44 × 44px. Mobile goal ordering and all plan-use controls meet a 44px height target. These are browser viewport checks, not physical-device keyboard certification.

27. Issues found and fixed

  • Updated the old two-goal validation and display assumptions without changing stored-profile schema.
  • Changed recommendation selection from a top-three allowlist to the complete enabled catalog.
  • Preserved duration tracking, notes and superset groups during catalog copying; the former copy path omitted them.
  • Adjusted deterministic ranking so small duration differences do not outrank a matching main goal.
  • Raised the mobile filter close target from 32px to 44px, added visible focus styling and restored focus after dismissal.
  • Updated old tests that expected dynamically rewritten six-preset routines to validate the new static catalog and ranking. Existing calorie, workout, ownership and data assertions remain covered.

28. Schema and dependencies

No schema migration, index change, Composer dependency or npm dependency change. Existing JSON goals, TrainingPlan/TrainingDay/TrainingExercise models and structured-workout identities are sufficient. The existing source-exercise-key index and completed-status Progress rules remain untouched and pass their regressions.

38. Limitations and next-release boundary

  • Templates are curated starting points with fixed prescriptions, not an AI coach, periodization engine or guaranteed outcome. Users adjust their own weights and scheduling.
  • Equipment categories are the existing canonical options. Home-gym inventory is not modeled item by item.
  • Ranking is deterministic and explained by actual matches; it is not a medical or physiological suitability assessment.
  • Selecting a plan never silently adds Calendar sessions. Existing explicit scheduling and workout protections remain in force.
  • Responsive checks use browser emulation, not physical iOS/Android hardware.
  • No v1.9.1 feature work has started. This release stops at v1.9.0.
